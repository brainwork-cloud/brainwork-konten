## Langkah
0. **Snapshot Seri (hanya run pagi 10:55, sekali per hari).** Tab `Seri` di Sheet: kolom A Tanggal, B Hari ke, C Followers, D Selisih, E Catatan. Kalau belum ada baris dengan Tanggal hari ini (WIB, `YYYY-MM-DD`): ambil followers dari `curl -s https://raw.githubusercontent.com/brainwork-cloud/brainwork-konten/main/performa/followers.json` (baris `kode` = `nopal-ig` dengan `tanggal` = hari ini WIB; diisi kolektor performa 06:47 WIB; kalau belum ada baris hari ini, pakai baris terbaru dan tulis tanggalnya di kolom E), lalu tambah 1 baris di bawah baris terakhir: Tanggal, B = `(hari ini - 2024-08-21)` dalam hari (19 Okt 2026 = 789), C = angka itu, D = C dikurangi Followers baris sebelumnya (kosong bila baris pertama), E kosong. Gagal mengambil angka: jangan mengarang, tulis di Log Agen.
1. **Antrikan posting IG.** Ambil baris `APPROVED`, Platform `IG`, Tgl Tayang = hari ini (WIB), Jam tayang ≤ 1 jam dari sekarang atau sudah lewat ≤ 8 jam (jadi konten jam 11:00 yang baru di-APPROVE siang tetap terbit di run 18:55), dan BELUM punya `queue/<ID>__instagram.json` di klon repo (kalau sudah ada, itu sedang menunggu atau sudah diproses: jangan unggah lagi, urus di langkah 2). Abaikan baris lain.
   0. Kredit foto: tidak perlu kamu urus lagi. publish.py menyamakan baris kredit di caption dengan `aset/<ID>/.foto.txt` otomatis (seperti Facebook). Kirim caption apa adanya.
   a. Cek dulu semua URL di kolom Aset dengan `curl -sI` (harus 200). Ada yang 404 → render di GitHub belum selesai atau gagal: lewati baris ini, tulis Catatan Review "aset belum ada (<URL>), coba run berikutnya", JANGAN ubah Status.
   b. Carousel (2–10 URL JPEG di kolom Aset) → unggah ke Kotak Masuk: `{"id": "<ID>", "platform": "instagram", "publish_at": <waktu sekarang WIB ISO +07:00, atau Tgl Tayang + Jam bila itu masih di depan>, "status": "approved", "message": <kolom Caption apa adanya>, "image_urls": [URL kolom Aset, urut]}`. 1 URL saja → `"image_url"`.
   c. Reels: `"video_url"` = URL `.mp4` penuh (baris pertama kolom Aset). Uji dry-run 26 Okt 2026: Instagram menerima file 10,3 MB lewat Graph API sampai container FINISHED, jadi batas ±4 MB hanya berlaku di jalur Windsor lama. `"cover_url"` = URL `_cover.jpg` di folder yang sama bila ada (cek 200). Selain itu sama dengan carousel. Kalau antrian itu berstatus `failed` dengan error diawali `RuntimeError: container Instagram` (Instagram menolak videonya SEBELUM tayang, tidak ada post), unggah ulang SEKALI dengan `"video_url"` = URL `_ig.mp4` bila ada (stempel baru); error lain jangan diulang.

2. **Sinkron hasil.** Dari clone, pertama untuk tiap `queue/<ID>__instagram.json`: `posted` → baris Antrian Status `POSTED`, Media ID = `result.id`, Link Post = `result.url`; `failed` → Status `GAGAL`, `error` singkat di Catatan Review dan 1 baris Log Agen (JANGAN unggah ulang otomatis kecuali kasus `container Instagram` di langkah 1.c: sebagian kegagalan terjadi setelah tayang, cek dulu akun lewat link profil). Status `tested` = uji jalur, abaikan. Lalu untuk tiap `queue/<ID>__facebook.json` dan `queue/<ID>__youtube.json` berstatus `posted`/`failed` yang belum tercatat di Sheet: posted → kolom X/Y = `OK <url hasil>`; failed → `GAGAL: <error singkat>` + 1 baris Log Agen. Kalau `inbox_gagal.txt` menyebut file yang kamu unggah run sebelumnya: perbaiki dan unggah ulang (stamp baru), catat di Log Agen. Kalau `tokens/status.txt` menyebut token FB/YouTube bermasalah: tulis di Log Agen "token <platform> perlu dibuat ulang, kabari Naufal", jangan antrikan platform itu.
